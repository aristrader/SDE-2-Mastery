## Tailoring rules

- Mirror exact required technologies from the job description only where they are true.
- Put the strongest matching keywords in experience bullets first; use skills as supporting evidence.
- Pair a keyword with scope, engineering decision, or result. Example: “Reduced API latency by 75% by
  removing redundant downstream calls” is stronger than a standalone “performance optimization” phrase.
- Do not add tools, cloud services, frameworks, metrics, or ownership claims solely for ATS coverage.
- Keep domain keywords optional for general backend roles; emphasize Java, Spring Boot, APIs, Kafka,
  databases, AWS, performance, and reliability first.
