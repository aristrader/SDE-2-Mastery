# OOP Pillars

The four OOP pillars are design concepts. Learn them together because interview questions usually compare them, not just define them.

## Study path

| Order | Page | Use it for |
| --- | --- | --- |
| 1 | `encapsulation` | Protecting state and invariants. |
| 2 | `abstraction` | Exposing a useful contract while hiding implementation detail. |
| 3 | `inheritance` | Modeling a substitutable IS-A relationship. |
| 4 | `polymorphism` | Runtime dispatch through a common type. |
| 5 | `composition_vs_inheritance` | Choosing HAS-A when inheritance is the wrong reuse tool. |

## Quick recall

- **Encapsulation:** protect internals.
- **Abstraction:** expose the right contract.
- **Inheritance:** model true substitutability.
- **Polymorphism:** dispatch behavior by runtime type.
